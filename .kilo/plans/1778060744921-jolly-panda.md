# Plan: Match Web and Mobile Features & Design

## Current State Analysis

### Web App (apps/web)
- **Entry**: `WorkspaceShell` → split-pane layout (document + workspace)
- **Features**: PDF viewing, excerpts, comments, text nodes, bookmarks, notes module, tag filtering, export (PDF/JSON), node linking, rich text formatting toolbar
- **Canvas**: Full infinite canvas with pan/zoom, node drag/resize, bezier link lines
- **Design**: Warm cream palette, soft shadows, rounded corners (20px), gradient accents

### Mobile App (apps/mobile)
- **Entry**: `DocumentExplorer` → document grid + viewer
- **Features**: PDF viewing, basic excerpts/comments, mobile workspace canvas, drawing tools (pen/highlighter/eraser/textbox), webpage import, navigation modal
- **Canvas**: Touch-optimized, pan/zoom, node drag/resize, simplified linking
- **Design**: Cool blue-grey palette, sharper contrast, mobile-first components

---

## Feature Gaps to Address

### Priority 1: Core Workspace Parity
1. **Notes Module**: Mobile lacks NoteNode/NoteEditor completely
2. **Text Formatting Toolbar**: Mobile toolbar less complete (missing preset styles, font options)
3. **Tag Filtering**: Web has tag-based filtering in document rail; mobile has no tag UI
4. **Link Layer**: Web shows curved bezier lines; mobile uses simpler SVG paths
5. **Export Modal**: Mobile exports are basic; web has full export modal with preview

### Priority 2: Design System Alignment
1. **CSS Variables**: Different variable names and color values
   - Web: `--bg`, `--panel`, `--text`, `--muted`, `--accent`
   - Mobile: `--mobile-bg`, `--mobile-panel`, `--mobile-ink`, etc.
2. **Component Styling**: Buttons, nodes, toolbars use different visual language
3. **Typography**: Font sizes, weights, spacing inconsistent
4. **Spacing & Borders**: Web uses 20px radius, mobile uses 8px

### Priority 3: UX Consistency
1. **Tool Rail**: Web has `WorkspaceToolRail`; mobile has `SourceSidePanel` + canvas tool rail
2. **Selection Popup**: Web has `SelectionActionPopup`; mobile has `SelectionActionPopup` (similar but needs styling match)
3. **Navigation Pane**: Web uses note sidebar; mobile has no equivalent
4. **Zoom Controls**: Different placement and styling

## Implementation Strategy

### Phase 1: Design System Unification
**Goal**: Establish shared design tokens without breaking existing apps

1. Create `packages/design-tokens` (or extend existing) with CSS custom properties:
   ```css
   :root {
     /* Unified palette */
     --color-bg: #f3efe6; /* web default, mobile can override */
     --color-panel: #fffaf2;
     --color-ink: #1f1b16;
     --color-muted: #5f5548;
     --color-accent: #1e6b5c;
     --color-line: #d9ccb2;
     
     /* Spacing */
     --radius-sm: 8px;
     --radius-md: 14px;
     --radius-lg: 20px;
     
     /* Shadows */
     --shadow-sm: 0 6px 16px rgba(31,42,58,0.1);
     --shadow-md: 0 14px 30px rgba(34,44,70,0.16);
     --shadow-lg: 0 24px 70px rgba(31,42,58,0.28);
   }
   ```

2. Update **web globals.css** to use unified variables (keep current values)
3. Update **mobile globals.css** to use unified variables (map mobile values to unified ones)
4. Ensure both apps reference same variable names for consistency

## Technical Considerations

### Shared State Management
- Current: Web uses `workspace-state.ts` + IndexedDB; mobile uses `mobile-store.ts` + IndexedDB
- **Action**: Ensure both use same domain models (`@workspace/domain`) and compatible serialization
- Keep separate storage namespaces (`workspace-web-local` vs `workspace-mobile-local`)

### Component Reuse Strategy
- Avoid direct code sharing (different platforms: Next.js web vs Next.js mobile with different UX)
- **但**可以共享:
  - Domain types (already via `@workspace/domain`)
  - Utility functions (`canvas-node-crud.ts`, `node-links.ts`, `pdf-selection.ts`)
  - CSS variables approach (single source of truth)
- Consider extracting `note-editor.tsx` to shared package if both use identical ProseMirror schema

### Migration Path
1. **Step 1**: Implement unified design tokens in `packages/domain` or new `packages/design-tokens`
2. **Step 2**: Update mobile CSS to use unified variables
3. **Step 3**: Add notes module to mobile (new files, integrate into store)
4. **Step 4**: Upgrade mobile workspace toolbar
5. **Step 5**: Add tag filtering to mobile
6. **Step 6**: Enhance link layer visuals
7. **Step 7**: Add export modal to mobile
8. **Step 8**: Polish styles across board

### Testing
- Run web typecheck & lint: `npm run typecheck --workspace @workspace/web`
- Run mobile typecheck & lint: `npm run typecheck --workspace @workspace/mobile`
- Manual testing:
  - Create/delete notes on both platforms
  - Apply text formatting (presets, fonts, sizes)
  - Tag filtering shows correct nodes
  - Links render with bezier curves on both
  - Export works and opens in web/mobile

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Mobile bundle size increases with notes module | Code-split note-editor; lazy load if needed |
| CSS variable conflicts with existing code | Use unique prefix (`--di-` for Document Intelligence) |
| IndexedDB schema differences cause data incompatibility | Keep separate DBs; no cross-platform sync required |
| Touch UX differs from mouse UX | Test on actual device; adjust hitboxes/target sizes |
